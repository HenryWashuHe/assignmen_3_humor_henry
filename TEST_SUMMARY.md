# Post-Testing Write-Up — Assignment 3

Owner: Henry He (sh4421@columbia.edu)
Date: 2026-04-24

I ran the full QA plan three times across the three apps (Caption App, Admin
Area, The Matrix). Below is the short version of what I exercised, what broke,
and what I fixed. The full branch-by-branch plan is in `QA_PLAN.md`.

- **Auth / access control** — Verified the gating tree on The Matrix on every
  pass: unauthenticated → `/login` (307); authenticated-but-unauthorized →
  `/unauthorized`; matrix-admin and superadmin both pass. The dashboard layout
  does the role check (not the Edge middleware), which avoids the
  `MIDDLEWARE_INVOCATION_FAILED` regression we hit earlier in the term.

- **Flavor authoring loop** — Created flavors three different ways (manual
  step-by-step, "Load Starter Pipeline" preset, "Load Columbia Roast Loop"
  preset). Edited slug/description, reordered steps via drag-and-drop, deleted
  steps, and duplicated flavors. Confirmed `/api/flavors/:id/duplicate`
  generates `<slug>-copy`, then `-copy-2`, `-copy-3` on collision, and
  rolls back the new flavor if step inserts fail.

- **Test Flavor pipeline** — Ran the full 4-step caption pipeline (presigned
  URL → PUT upload → register image → generate captions) against (a) an
  uploaded image and (b) a study set in single and batch mode. Found that
  batch mode previously fired `Promise.all(setImages.map(...))` with no
  concurrency cap — a 30-image set would slam the API in parallel. **Fixed
  by adding a `BATCH_CONCURRENCY = 3` worker pool** in
  `app/(protected)/test/TestFlavorClient.tsx`. Per-image errors no longer halt
  the rest of the batch.

- **Memory leak in image preview** — On repeated uploads in Test Flavor, each
  `URL.createObjectURL(file)` was leaking because we never revoked the prior
  blob URL. **Fixed with a `useEffect` cleanup** that revokes the previous
  preview URL on change and on unmount. Caught this by re-uploading 10+
  images in one session and watching the blob list in DevTools.

- **Captions browser** — Pagination works at boundaries (1 page, 7+ pages with
  ellipses), flavor pill filter resets to page 1, missing image URLs render a
  placeholder instead of a broken `<img>`, and request/chain id pills appear
  only when present.

- **API contract sanity** — Smoke-checked every route via curl in dev:
  unauthenticated `GET /api/flavors` redirects (middleware), authenticated
  CRUD returns the documented `{ success, data?, error? }` shape. The
  `/reorder` route correctly rejects empty arrays with a 400 instead of
  silently no-oping. Removed dead code (`stepTypeIcons` / `getIcon`) in
  `components/StepPipelineViz.tsx` that lint would have eventually flagged.

- **Cross-app integration** — Verified the round-trip: a flavor created in
  The Matrix becomes selectable in the consumer Caption App, captions
  generated by that flavor surface in both the Matrix Captions browser and the
  Admin Area caption review. Granting/revoking `is_matrix_admin` from the
  Admin Area takes effect on the user's next Matrix navigation.

- **Build + types** — `npm run build` and `npx tsc --noEmit` are both clean
  on every iteration after the fixes above. Final build:
  13 routes, no warnings.
